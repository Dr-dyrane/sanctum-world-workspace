# Reviewer Failure Patterns

## Source-Of-Truth Rule

Extracted from source guide mentions of GO, SEND BACK, reviewer expectations, AutoQC reliability, and common failure modes.

## GO / SEND BACK Logic

- Brainstorm checkpoint output is binary: GO or SEND BACK.
- If sent back, revise and re-present.
- World Spec review similarly returns approval or needs fixes.
- Do not proceed beyond the current gate until the required review approval is received.

## Reviewer Expectations

- AutoQC should be run at every stage and taken seriously.
- Reviewer feedback officially lives in RL Studio.
- Slack can be used for clarification, but the official record stays in RL Studio.
- Reviewers expect every flagged AutoQC issue to be addressed or explicitly documented as a disagreement.
- The source guide states spec-stage AutoQC is particularly reliable; unresolved issues will likely become reviewer feedback.

## Common World Spec Rejection Reasons

- Spec does not follow the official template structure.
- Sections, headings, column names, IDs, or naming conventions are changed.
- Clinical facts are vague, inconsistent, or not traceable.
- Dates in task prompts, traps, files, filenames, and Key Milestones do not match.
- Task prompts are not naturalistic or appear AI-written.
- Task prompts were generated by LLM instead of the physician writer.
- Expected outputs are not precise enough to grade.
- Failure Design lacks 5-6 high-yield traps or clear remediation paths.
- Traps and frictions are confused.
- Task anchors occur inside the world timeline or before latest world file date.
- Tasks depend on outputs from other tasks.
- Files were designed before tasks.
- Essential and supplementary files are misclassified.
- Supplementary files carry answer-changing information.
- File plan lacks complete columns or source/template origin.
- Single files resolve tasks without synthesis.
- World relies on rare diagnosis puzzle design instead of realistic workflow complexity.
- Claude has introduced unsupported clinical content, file content, dates, doses, or template material.

## Common Onboarding Failure Patterns

- Moving into World Spec before Brainstorm GO.
- Moving past Step 6 into synthetic generation, production task setup, golden responses, grader guidelines, FA, or PL.
- Treating Claude as the author instead of as assistant.
- Not preserving source docs separately from generated work.
- Not keeping physician judgment as source of truth.
- Failing to document reviewer feedback and AutoQC results.
