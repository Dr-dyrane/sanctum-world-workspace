THE LAW (read FIRST, before any step): docs/reasoning-discipline.md "THE LAW" section. Four lines, one law: (1) build it real, no watering down; (2) build the task with the world's per-artifact micro-step rigor, the task deserves more rigor than the world; (3) read every file in full and reason from the full context to OUTSMART the model, not feed it, we know its exact information set; (4) difficulty is empirical and adversarial, not architectural, discover the discriminator by running the model and exploiting where its competence forces an error, a complete task is not an adversarial one. GOVERNING PRINCIPLE: docs/reasoning-discipline.md (the verification gate). At every one-way door (expensive/irreversible commit) or any claim about WHY a system behaved a certain way, read the ground truth (config/transcript/output) BEFORE committing; state verified vs inferred. Stay fast everywhere else. Most of this runbook's "expected residual / justify vs fix" calls ARE one-way doors - verify first.

## A0. Reviewer-driven defaults (Abi first + second review, Task 1) - bake these in from the START, do not rediscover
- ENGINEERED FAILURE MODE (Abi second review, Task 1, 6/6): a clean, realistic, correctly-reasoned task is NOT enough. If all 10 trajectories score >=90 with no significant clinical failure, the task is "too easy" and CANNOT clear, even with perfect realism. Every task must ship with a designed failure mode that produces at least one trajectory <90 (target <70) AND a genuine clinical failure. The most reliable lever is an adversarial-authority input: a realistic, authoritative task file (e.g. a pharmacy/consult handoff, signed by the one plausible author, accurate dates) that makes a plausible but WRONG/unsafe recommendation which directly contradicts evidence already in the chart. Correct behavior = catch and decline it; failure = adopt it. Build the golden to explicitly decline the trap and the grader guidelines to require declining it (Must) and penalize adopting it. This re-frames the "no task files" default below: a task file is justified when it carries an adversarial trap the chart can rebut, not when it enumerates the answer. Concentrate the hardest stumping in synthesis tasks (KM04, KM06). CRITICAL REFINEMENT (two independent red-teams 6/6): a buried fact will NOT produce failure (a strong model finds it); a chart-COACHED wrong recommendation will NOT either (the model sides with the chart); and a famous-fact error (e.g. TMP-SMX/nitrofurantoin in CKD) will NOT either, because a medication-SAFETY-review task explicitly primes the model into maximal find-the-error mode, so ANYTHING that pattern-matches as an error gets caught. THE DISCRIMINATOR MUST NOT LOOK LIKE AN ERROR: a tempting wrong action disguised as safe/routine counseling, requiring INTEGRATION (not recall) to reject, and placed in the SAFE-items cluster (not beside the obvious med errors, or error-hunting sweeps it up). VERIFY trap premises by reading the FULL live note verbatim (not keyword-grep, not pipeline files) - a v5/v7 ARNI item was built on a 'conditional door' that existed only in pipeline markdown, the finalized chart said the opposite (validity bug). Reusable Task 1 build: task-setup/platform/task1/medication_safety_handoff_pharmacy_05232026.docx (CENTRAL = potassium-based SALT SUBSTITUTE as routine low-sodium diet counseling buried in safe-items paragraph = uncoached integration hyperkalemia trap; ANTIBIOTIC ANCHOR = nitrofurantoin switch = fair/capped, decline for septic-upper-tract source + eGFR; TERTIARY = prednisone-5mg-from-fill, coached/low-weight; ARNI = home-dose restart, correct answer DEFERS/stages per live nephrology). De-gate the cap (hard cap only for an unflagged indefensible agent). Grade ADOPTION not mention. PILOT + re-grade the prior passing transcript before trusting any sub-70.
- FA/GA PROSE FORM (Abi second review, 6/6): write FA and GA as natural prose, complete sentences, NO bullets and NO headers. Still single lowest run, still 2-3 sentences each on what the model failed / did well (FA) and what the grader got right / wrong (GA). Abi sample voice: "On trajectory N, the model did well on the anchor points. It [did X, Y]. The main model failure is that it [Z]." Plain narrative, not a structured list.
- TASK FILES: a task file earns its place ONLY if it carries evidence required for the task that does NOT exist in any world file. A "request memo" or "handoff" that just enumerates/structures what the chart already holds = answer leakage; it inflates scores and gets deleted. Default to NO task files unless a real gap exists. If a task file IS needed: realistic clinical doc, signed by the one plausible author, minimal info, dated to the task date (not after), no "Date/Anchor" or "anchor" project artifacts.
- GOLDEN: build as a FULL chart document from the first draft - letterhead, demographics (DOB/MRN/allergies/code status), a date matching the task date, and a signature block. Then the clinical body in committed register. (Task 1 lost a round because the golden was body-only.)
- GOLDEN HEADER: include the hospital/clinic/location name in the header for realism. Abi explicitly checked this on Task 1 round 2.
- DATE AUDIT (Abi first review, Task 2, 6/7 - the golden-date miss): pin the IN-WORLD TODAY from the LIVE prompt first, then make every artifact match it: golden header date AND identity-band Date cell, task file dates (header, body mentions, Date cell, filename stamp), grader task-context dates, README records. A FRAMING CHANGE (clean to escalation, prompt rewrite, reseed, anchor shift) makes every surviving artifact UNVERIFIED until re-checked against the new today; "it passed under the old framing" is not verification. KM02 shipped a 05/23 golden into a 05/24 escalation this way. Sweep ALL surviving artifacts, not just the file being edited. See AGENTS.md guardrail 5 + docs/reasoning-discipline.md FRAMING-CHANGE RE-AUDIT.
- GRADER GUIDELINES: mechanism-agnostic, judged against the golden (A0/A3). Self-Contained + No Weight Distribution warnings may recur in this pattern; read the exact flag text, rerun variance-like failures once, and justify only when the same evidence supports it.
- FA/GA: single lowest run only, Abi's format (D2). Natural prose with complete sentences, not bullets; remove headers in the submitted text. Never "the two lowest"; never "what I missed"; never "grader went into the chart."
- TRAJECTORY DIFFICULTY GATE: a task cannot clear if all 10 trajectories are >=90. There must be a significant clinical failure and at least one trajectory <90; <70 is preferred when possible but not absolute. If a cleanup makes the task too easy, harden/redesign before resubmission.
- VARIANCE flags (No Formatting Leakage, No Weight Distribution): "Rerun N failing" ONCE before justifying; they often clear (same file/structure that passed a prior run).
- WORLD-FILE FORMATTING: do not use alert-color or emphasis highlighting in any file carrying trap-relevant content (invites No Formatting Leakage variance). Reserve color/bold for uniform document chrome only.
- WORLD #2 HEADER CONVENTION: do NOT use the "Date / Anchor" header-label convention in world files (it is a Sanctum project artifact, not a real clinical header, and it leaks into agent output; Abi flagged it on task files). Use real clinical fields ("Date of Service", "Hospital Day", "Encounter Date"). Verified 6/6: present in 19 of 26 Korvin world files; left as-is because the world is FINALIZED + passed Final Files 78/78 and editing a live world mid-review is a high-cost one-way door no reviewer required. Fix at BUILD time in World #2, not by re-opening a finalized world.
- DO NOT re-open a FINALIZED/live world for cosmetic fixes (header labels, structural bold). It invalidates synced trajectories and destabilizes a passing world. Only re-open if a reviewer flags the WORLD specifically, or a hardening change is explicitly authorized. Verify the actual files (python-docx text extraction, NOT grep on the zipped .docx - grep on binary docx gives false negatives) before deciding.

## D2. Failure Analysis & Grader Analysis (Task 1 lessons)
- [ ] Pull the GRADING TRANSCRIPT for the single lowest run BEFORE writing FA/GA. Do not infer the failure mode from the output alone.
