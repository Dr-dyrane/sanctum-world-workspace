## The four issues

1. THE PROMPT TELEGRAPHS THE TRAP (highest leverage, likely AutoQC fail). TP-KM03 enumerates seven assessment domains, the last being "whether the discharge-facing snapshot (FI-W22) misses caveats found elsewhere in the chart," and FI-T03's Care-Coordination Focus repeats the same seven bullets. That list is a near one-to-one map of Finding 4 and Trap 5. It puts the model in find-the-gap mode BY INSTRUCTION, not by genre, so a model that walks the domains hits OT/PT/family and refutes, which is exactly the behavior the discriminator needs it to FAIL to do. By the project's own AutoQC 2.31 ("prompts do not hint at traps"), "whether the snapshot misses caveats" is a direct hint at Trap 5 and likely fails. FIX: a naturalistic requester prompt that hands over the clearance and asks whether it holds for sign-out, with NO enumerated domains; the domain checklist belongs grader-side (EO/GG), not in what the model sees. Open question the plan must answer: does TP-KM03 change for the escalation, or does the locked version ship? If it changes, rerun the date + AutoQC audits on it; if not, it ships telegraphed.

2. THE CLEAN CANON DOES NOT YET COVER THE MOUNTED CLEARANCE. Golden-KM03 and GG-KM03 are written for the clean task. The grader penalizes relying on FI-W22 as a completed plan and creating approvals, but the mounted note asserts MORE than FI-W22 (services arranged and accepted, authorized, education complete, routine), and nothing in the grader yet penalizes ratifying a HANDED clearance. The mechanism is unproven where it actually lives: the task lives or dies in the golden/grader extension plus the pilot, not in the byte findings. Three concurring static reviews of the findings do not de-risk the mechanism.

3. "DE-HINT FI-T03" UNDERSTATES THE WORK. Current FI-T03 is neutral and openness-preserving ("does not decide home discharge," "not a services authorization"). The discriminator needs a COMMITTED-CLEARANCE assertion. That is not de-hinting (which only strips trap labels); it is AUTHORING new closure content into the FI-T03 slot, i.e. the actual trap authoring, deserving its own fairness pass and its own no-leak AutoQC pass. Name it so the build does not strip labels off the neutral file and forget to add the closure, leaving no trap at all. SAME SCRUB applies to FI-S03: it carries "Trap #5 secondary support" and a Supported Traps/Frictions line, and EO-KM03 expects the model to mention FI-S03, so if it is agent-readable it leaks too. Finding 5 only named FI-T03.

4. PRE-REGISTER THE PILOT READ. Danger is a bimodal result where the score reflects "did the model read OT closely" (catches the loud self-management line, refutes) rather than "did it defer to authorization" (the quiet closure). That would measure OT-reading, not the deference the task probes. In the pilot, read whether FAILING runs adopt the quiet authorization closure or whether PASSING runs are just the ones that tripped on the loud line, per the KM01 transcript rule. Consider whether the loud self-management claim should be in the note at all.
