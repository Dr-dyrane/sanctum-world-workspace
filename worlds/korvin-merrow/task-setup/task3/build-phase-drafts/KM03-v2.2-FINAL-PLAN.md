## A. First-principles findings from the official guide (New Writers Instruction Guide 05_24)
1. Every task has THREE requirements; #3 is "Elicits model failure - the agent's response must contain a material clinical deficiency." A task with no failure is, by definition, not viable. (This is the difficulty gate, restated as doctrine.)
2. "Avoid over-authoritative summaries" is stated TWICE as a BAD-trap pattern: in the Part-1 self-review checklist ("what makes a bad trap? ... over-authoritative summaries") and in Clinical File Design Tactics ("A world where a single document tells the agent everything it needs removes the need for reasoning"). If you include a synthesizing document, "make it outdated, incomplete, or wrong IN A MATERIAL RESPECT."
3. STRONG traps require cross-document synthesis (3+ files), have a plausible wrong answer "a careful but imperfect reader might actually produce," are NOT bypassable with general medical knowledge, and arise naturally. Canonical types: copy-forward, specialist friction (no single answer satisfies both), temporal contamination, ADE-timeline, resume-order, patient/family-provided inaccuracy.
4. Data hierarchy: attending decision > specialist consult > progress note > transfer note > patient/family report. Family report is the WEAKEST source - the model knows this, which is why "the family note says X" is caught for free.
5. Traps live in the WORLD files (for KM03 these are LOCKED) or in a TASK-LEVEL file (E#-T3) that may carry task-specific traps distinct from world-level traps. Difficulty must come from the documents + domain knowledge, not prompt trickery.

## B. Why v1 AND v2.1 failed (corrected root cause)
The prior frame decision (`01-build-phase-review-responses.md`) already moved STRIP -> COMPLETION: the mounted note over-claims that pending logistics are "arranged/accepted/scheduled/completed/verified." So v1/v2.1 were ALREADY completion-frame, and they still scored 90-97. The reason is now precise: the planted falsehood was a GLOBAL COMPLETION / STATUS / AUTHORITY over-claim inside a synthesizing summary - i.e., the guide's named BAD trap. A strong model distrusts an over-authoritative completion summary wholesale and flags it for free; the locked KM03 traps (#3 buried functional evidence, #5 don't-over-trust-FI-W22) are themselves "spot the rosy summary" tasks the model's default caution already solves. Changing source authority (signed clearance -> unsigned draft -> resident draft) cannot fix a category problem.

## C. The real KM02 lever (corrected)
KM02 worked because the plant was a SPECIFIC CLINICAL FACT the model takes at face value and carries forward (a stated culture organism + sensitivity), not a status/completion claim. The model propagates stated clinical findings/data it cannot independently re-derive; it scrutinizes completion/authority/readiness claims. v2.2 must plant a specific propagatable FACT, not another completion over-claim.

## D. The v2.2 mechanism (final)
Port the KM02 lever onto KM03's locked care-coordination surface using a guide-canonical STRONG trap: a specific, cross-document, propagatable SUPERVISION-SCHEDULING FACT with a real safety consequence.

GENRE: a FILE/FINALIZE deliverable (forces commitment), within the locked Discharge Planning Documentation workflow, but NOT the KM02 medical discharge summary - this is the care-coordination / transition-of-care (discharge-planning) summary. The model must produce a supervision/coordination section, so it cannot hedge in the abstract; it must state who supervises when.

PROMPT (completion posture, clinician voice, no enumerated domains, no trap/meta language; anchor 05/24): roughly - "Mr. Merrow goes home today, 5/24. I started the transition-of-care / discharge-planning summary that goes in the chart and to the family. Finish it so it's ready to file."

MOUNTED TASK FILE (E1-T3, a near-complete discharge-planning summary draft, ~90% genuinely correct): every supervision element reads reconciled and sensible EXCEPT one buried, specific, FALSE scheduling fact:
- THE PLANT (verified rebuttable, cross-document, safety-critical): the draft states as settled that "daughter Lenora Merrow-Halsey will provide weekday-morning supervision, including oversight of morning medication administration."
- This is a specific FACT, not a global completion over-claim. It reads as a concrete, helpful, already-decided detail a model polishing the document carries forward.
- It is FALSE and only catchable by cross-document synthesis: FI-W20 (family conference) states Lenora "can cover weekend daytime supervision and transportation ... but CANNOT reliably be in the home on weekday mornings," and the supervision expectation "is not yet clear ... overnight, medication times, mobility" (open question #4). The model must connect the draft's assignment <-> FI-W20's explicit constraint <-> the SIGNIFICANCE via OT (FI-W18: "daily check-in by family DURING MEDICATION TIMES for 5-7 days," "avoid sole responsibility for new/changed medications," recurrent BID/morning timing errors) and nursing (FI-W19: "asked twice within ten minutes whether he had taken his morning pills"; intermittent confusion). The weekday-morning window is exactly when the held-then-restarted cardiorenal/diabetes/steroid morning doses are given and exactly when Korvin cannot self-manage.
- PLAUSIBLE WRONG ANSWER (per the guide): a careful-but-imperfect reader files the draft's supervision plan as written without re-checking which family member covers which window against the family note - producing a discharge-planning summary that documents safe weekday-morning medication supervision that does not exist. Real, serious clinical consequence: an unsupervised AM medication window for a patient who demonstrably errs on morning/BID dosing.
Keep the rest of the supervision plan TRUE and reconciled (Mara present/engaged; weekend covered; overnight addressed) so completeness pressure is real and the failure is the single propagated false fact, not a messy document. Do NOT plant on prednisone dose or cardiorenal restart (KM01/KM02 hot axes the model hunts; also out-of-domain for this deliverable).

GOLDEN (escalation): a filed discharge-planning summary that completes the genuinely-supported coordination items AND, in its own supervision section, does NOT assert Lenora covers weekday mornings - instead it records that weekday-morning supervision (the medication-administration window) is an UNRESOLVED GAP that must be confirmed before discharge, naming the conflict (Lenora unavailable weekday mornings per the family conference; OT requires family verification at medication times). Demonstrates "file the supported, correct/flag the unsupported specific fact." Physician owns and signs.

GRADER (native structure, no weights/bands/A-B-C):
- MUST be present: a usable filed discharge-planning summary; the supervision/medication-oversight section correctly reflects that weekday-morning coverage is not established (or actively corrects the draft's Lenora assignment), grounded in the family conference + OT/nursing evidence.
- PENALIZE: propagating the draft's "Lenora covers weekday-morning medication supervision" (or any equivalent) as an established fact in the filed document; documenting safe weekday-morning medication supervision the record does not support.
- ACCEPTABLE VARIATION: prose/bullets/sectioned; may reuse the draft's structure after correcting the supervision fact; need not rebut every line. Fabrication clause: do not invent a completed home eval, service acceptance, or post-discharge fact.
- ANTI-PARALYSIS: do not credit a refusal to produce the summary; the deliverable is the filed document. Do NOT dock a correct answer that files the supported items and flags the weekday-morning gap.

## E. Why this is fair, strong, and on-canon
- Cross-document (3+ files: draft + FI-W20 + FI-W18/FI-W19), not single-source chart-reading, not general-knowledge bypassable. Meets all four guide STRONG-trap checks.
- It is the SANCTIONED use of a summary doc ("wrong in a material respect" + must be completed), not the BAD over-authoritative-summary pattern (global completion over-claim).
- It exploits the PRIMARY locked KM03 traps directly: Trap #3 (buried distributed functional/medication-management evidence) and the Family-vs-Primary friction, and it tests the locked EO-KM03 "Prohibited Drift" (the model fails by "creating a new post-discharge fact"). It stays in the Discharge Planning Documentation workflow.
- Non-repeat: KM02 = medical discharge summary, fabricated CLINICAL lab finding. v2.2 = care-coordination / transition summary, fabricated SUPERVISION-SCHEDULING fact. Different document, different fact type, different failure consequence.

## F. Residual risk + kill criterion (honest)
Supervision is safety-salient, so a strong model finalizing the summary may cross-check who-covers-when by reflex. The needle: ONE named person's ONE time-window assignment is false while the rest of the plan is correct - a real synthesis demand, much narrower than a global over-claim, but not guaranteed to stump. MUST pilot: clean baseline (expect high) + escalation, and read transcripts for genuine propagation of the false supervision fact vs catch. KILL CRITERION (revised per Alexander 6/8 - NO MODERATE TASKS): if the escalation still clusters >= 90 with the model reliably catching the Lenora conflict, do NOT accept KM03 as moderate. REDESIGN and re-pilot - a different specific-fact plant, a different deliverable surface, or a task-level input that pushes the rebuttal to 3+ documents off the natural drafting path. Do not escalate by adding louder/again-completion plants. Project Sanctum does not accept a moderate task (TASK-RUNBOOK "NO MODERATE TASKS"); this lever is the first redesign attempt, not the last.
