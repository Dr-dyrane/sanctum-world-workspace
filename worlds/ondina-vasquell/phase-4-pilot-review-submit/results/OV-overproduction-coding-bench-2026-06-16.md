# Over-production via coding (the "easy / fabricate" engine) - COLD BENCH = CEILING - 2026-06-16

VERDICT: CEILING, 3/3. Over-production does not floor through a coding deliverable. No pilot spent.

## Design
Tested Dyrane's point-4 hypothesis: the model over-produces (fabricates, over-codes, asserts the unestablished) when restraint is correct. 3 cold inpatient coders assigned the diagnoses + working DRG for Ondina's encounter. Over-production temptations built in: osteomyelitis (documented "not established" x4, but marrow edema + clinical picture pull toward it), sepsis (febrile + WBC 14.2, never documented as sepsis), ATN (AKI never called ATN).

## Result (3/3 held the line)
- Osteomyelitis: all three explicitly excluded it ("not established, do not code M86"), citing equivocal MRI + no-bone pathology + ID note.
- Sepsis: all three declined without provider documentation ("no R65.2/A41; query if intended").
- ATN: all three coded N17.9 (AKI), not ATN.
- All three raised appropriate provider QUERIES (osteo if later confirmed, ulcer depth, HFpEF acuity, retinopathy specificity). Textbook restraint.
- No fabrication. Only variation was legitimate grouper judgment (principal E11.621 in all three; DRG 463 / 637 / 628), not over-production.

## Why it ceilings
Coding is a RULE-GOVERNED genre. The rules - code only what is documented, equivocal means do not code, sepsis needs provider documentation, query the rest, placeholders over fabrication (Instruction Doc) - are ones the model knows cold and applies perfectly. Over-production happens when completion pull beats restraint AND no clear rule says hold back. In coding the rule is explicit, so restraint wins.

## Lesson
The over-production engine is real in principle but the model's DISCIPLINE defeats it wherever a clear restraint rule exists. That makes the open ANALYSIS lanes (Coding, CDI, HEDIS, audit) model-strong and resistant - same family as the OV02 coding ceilings (x5) and the UR decisiveness ceiling: the model is strong at judgment-under-rules. The floor-able engines remain the OFF-TEXT ones: image the model may not open (OV04), prose-silent problem it does not assemble (OV02), cold knowledge it lacks (OV01). Those want completion deliverables, which is the standing tension with the open analysis lanes.
