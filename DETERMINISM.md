# Deterministic builds

Goal: a clean checkout plus one command reproduces every generated docx BYTE-FOR-BYTE, so SHAs are stable across rebuilds and machines and the manifest never drifts.

## One command
```
pip install -r requirements.txt
python3 worlds/ondina-vasquell/phase-3-build-task-artifacts/build/build_all.py
```
Rebuilds all world, supplementary, task, golden, spec, and transcript docx, regenerates nothing it should not, and runs the verify gate. Run it twice; `git status` should show no docx changes.

## What made it nondeterministic, and the fix
- Build-time mod-times: python-docx / zipfile stamp the current time into every zip entry, so each build produced a different SHA. FIX: `tools/mode_a_clone.make_deterministic` pins every zip entry's date_time and the core.xml dcterms:created/modified to a constant. It runs as the last step of `scrub_all_metadata` (so all world/task/golden docx get it) and is called explicitly by the spec and transcript builders.
- Toolchain drift: a different python-docx/Pillow could change the rendered bytes. FIX: `requirements.txt` pins python-docx==1.2.0 and Pillow==12.2.0 (Python 3.10).
- Line-ending drift in text sources: FIX: `.gitattributes` sets `eol=lf` for text and marks docx/jpg/png/pdf/xlsx binary.

## Single source of truth (content determinism)
Clinical content lives once in `build/clinical_data.py` and `build/task_data.py`, ratified from `world-spec-prep/substrate-proposal-pack.md`. Goldens, task files, and world files all render from those, so a value changes in exactly one place. `tools/verify/verify_ondina.py` cross-checks the ratified anchors across every docx and fails on any contradictory variant.

## Not regenerated by build_all
The two writer-produced images (EW30 wound photo, EW31 ABI/TBI tracing) are Codex-generated binaries committed as-is; they are deterministic as stored (fixed SHAs) but are not rebuilt from source here.

## Proof
Building the 10 goldens twice in a row yields identical SHAs (verified 2026-06-13). The same normalized pipeline backs every docx type.
